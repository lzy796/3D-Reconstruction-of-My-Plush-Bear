## 4. 已核实的技术事实

> 「证据」= 我怎么确认的。凡是没写证据的结论，都不能当作事实使用。

| # | 事实 | 证据 |
|---|---|---|
| F1 | GLB 里**只有** `POSITION` + `TEXCOORD_0` 两个属性，**没有法线、没有切线、没有毛发几何** | 解析 GLB 的 accessor / primitive 列表 |
| F2 | GLB 材质只有一个普通 PBR：`baseColorTexture` + `roughnessFactor=1.0`；`metallicFactor` 未写，按 glTF 规范默认 **1.0（全金属）**；`doubleSided=false` | 解析 GLB 的 materials JSON |
| F3 | GLB 的贴图是 **1024×1024、RGB、无 alpha**。也就是说"绒毛"在这份文件里只存在于这张贴图的明暗里 | 从 GLB 的 bufferView 中提取 PNG 并用 Pillow 打开 |
| F4 | PLY 是标准 3DGS：96,760 个点，属性 `x y z nx ny nz f_dc_0..2 opacity scale_0..2 rot_0..3`；**只有 0 阶球谐**（没有 `f_rest_*`）→ 颜色与视角无关 | 解析 PLY 头 + 统计各属性 |
| F5 | PLY 的 99.9% 点 `opacity>0.5`，几乎不需要剔除坏点 | 同上 |
| F6 | **坐标系不同**：PLY 是 Z 向上、脸朝 **−Y**；GLB 是 Y 向上、脸朝 **+Z**。两者尺寸一致（约 1.00 × 0.96 × 0.62），换算关系是绕 X 轴 −90°：`(x, y, z)_glb = (x, z, −y)_ply` | 包围盒 + 四视图投影 + Blender 里从 −Y 渲染出正脸（见 F11/F12） |
| F7 | 熊的朝向已用渲染确认：**从 −Y 看是正脸，从 +Y 看是后脑**。`work/ply_ortho_views.png` 已按此更正标注（早先版本标反了） | `work/align_splat_back.png`（相机在 −Y）里能看到眼睛、鼻子、领结 |

## 6. 技术路线

**三句话：**

1. **`object_0.ply` 当最终外观主体**（Blender 5.3 原生支持 gsplat，能直接渲染出用户满意的绒毛）。
2. **`object_0.glb` 当"贴图案用的参照曲面"**（它是网格，有 UV，可以被精确选中、投射、导出）。
3. **从背面照片 89 标定一台相机 → 把照片投到 GLB 的背片上 → 做成贴片 → 和 splat 一起渲染。**

**为什么不用"多视角模型重新生成一遍"：** 现有的 splat 已经解决了形状和毛绒，重跑只会破坏已经满意的部分；而徽章、文字这类图形细节，只有真实照片能逐字还原（生成模型会"编"出似是而非的字）。

**为什么不用"直接改 splat 颜色"：** 96,760 个 splat 分布在整只熊上，背片徽章区域大概只有一两千个点；把照片投到这么稀的点上，文字必然糊成一团。贴片是一块真正的三角形网格，能承载任意分辨率。

## 10. 风险与已知限制

- **Blender 5.3 的 gsplat 编辑能力很初级**（官方原话：点云编辑工具"开始显得笨拙"）。所以路线是"在旁边加贴片"，不是"改 splat"。
- splat 是**自带光照的辐射场**：它不接收场景灯光。贴片若用普通 PBR 材质，会被场景灯再照一遍，容易比周围亮或暗 → 贴片要用「贴图同时接 Emission」的混合方式。
- EEVEE 的 gsplat 用抖动透明（dithered），需要**提高采样数**，否则有噪点。
- GLB 网格只有 17.5k 面、贴图 1024²，背片本身是 SAM3D **猜**出来的，形状误差会直接导致贴片错位。
- GLB 的 `metallic=1.0`、`doubleSided=false`：在 Blender 里先改成 Metallic 0、勾选 Backface Culling 关闭，否则颜色判断会被误导。
- **绒毛观感可能不如网页预览**（F15 未定论）：如果确认是引擎差异，可改用 Cycles 或 SuperSplat 出预览图，但 `.blend` 工程仍以 EEVEE 为主。
- 64 张照片跨场景、跨光线，**不能**用来做严格摄影测量；本方案本来也不依赖它。
